Privacy policy

RamAltman Windows · Effective November 9, 2026

RamAltman Windows is a personal Windows application that sends a memory report from the account you authorize to a recipient you configure. This policy describes the standalone Gmail OAuth implementation and this static information site.

Google information and permissions

The Gmail integration requests gmail.send, openid, and email. It uses Google account information to confirm that the verified email address of the account granting consent matches the configured sender. It receives an account identifier, that email address and verification status, the granted permissions, and authorization tokens with expiry information.

The application uses these permissions only to identify the authorized sender, maintain that authorization, and send the memory reports you enable. It does not request Gmail inbox, message-reading, or contacts permissions and does not use Google information for advertising, sale, profiling, or model training.

RamAltman Windows' use and transfer of information received from Google APIs follows the Google API Services User Data Policy, including its Limited Use requirements.

Information stored on your PC

  • Local configuration contains the sender and recipient addresses, optional sender display name, delivery settings, threshold, and local file paths.
  • Google access and refresh tokens, account identity, and expiry information are stored together as Windows DPAPI ciphertext. Decryption is tied to the Windows user and computer that saved them.
  • The Google Desktop OAuth client JSON is kept locally in the application's private folder. It identifies your own Google Cloud OAuth registration.
  • Local usage history records timestamps and memory figures. Local delivery state records the daily outcome, template rotation, and latest delivery receipt, including sender, recipient, subject, RAM figures, a body hash, and Gmail message identifiers when available. Event logs record timestamps and outcomes.

Default private files stay inside the application's local project folder and are excluded from its Git source. The monitor has no hosted token store or application backend. The Gmail option does not collect or save your Google password. Keep the private folder and any backups under your control.

Information sent in reports

When enabled and the configured RAM threshold qualifies, the application submits an email to Google for delivery to your configured recipient. The email contains the sender and recipient addresses, optional sender display name, subject, and a snapshot of total, available, and used physical RAM with its available percentage. If supported, it adds GPU model names and separate VRAM capacity figures.

One report is permitted per local calendar day. Delivery to a recipient is the purpose of the application: that recipient and their email provider receive the report. Google processes the authorization and email delivery under its own terms and privacy policy. Sent messages and recipient copies may remain with their respective email services.

Retention, disabling, and removing access

Run Disable.cmd to stop automatic monitoring and delivery. Disabling retains your local settings, encrypted authorization, and history so that you can enable the monitor later. Local logs are bounded by the application's retention limits; settings, tokens, and the latest delivery state remain until you replace or remove them.

To remove Google permission, first disable the monitor, then remove its access from Google Account connections. To remove local data, delete the configured token file and other files in the local private folder after the monitor is stopped. Local deletion does not delete emails already sent or copies retained by Google, recipients, or backups you maintain.

This information site

These static pages contain no analytics scripts, advertising, forms, or application sign-in. They do not receive Google authorization callbacks or tokens. If published through GitHub Pages, GitHub processes website requests and logs visitor IP addresses for security under the GitHub Privacy Statement. Following an external link takes you to that provider's service.

Questions and changes

Source and support are available at github.com/Slyrae/ram-altman. Use the repository's support channel, without posting private configuration or authorization files. Material changes to the application's data practices should be reflected in this policy and its effective date.
